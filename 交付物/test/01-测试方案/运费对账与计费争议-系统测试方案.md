# 物流费对账与计费争议系统 —— 量化测试方案

> 版本：v1.0　|　适用对象：主项目（`src/logistics_agent`，FastAPI + RAG + JWT 双角色）与 MVP（`mvp/`，分层架构 + Agent 白名单 + 三级审核）
> 编写依据：`domain.py` 业务规则、`policies.md` 制度语料 P-01~P-08、`app.py` 接口与错误码表、需求方案验收标准 AC-01~15、访谈量化指标（f 系列）

---

## 0. 文档说明

### 0.1 目的
以「正常 / 边界 / 对抗 / 权限 / 故障」五类场景，对系统给出**可执行、可度量、可追溯**的测试方案。每一条用例都绑定：输入、预期（精确值/状态码/错误码）、量化判定阈值，杜绝"大概对一下"式的验收。

### 0.2 被测系统与测试对象

| 层 | 主项目（生产形态） | MVP（演示形态） |
|---|---|---|
| 传输层 | `app.py`：SSE 问答、登录、后台、探针、指标 | `app.py`：核对/问答/草稿/三级审核 |
| 编排层 | `agent.py`（模型决策 + 工具调用） | `core/agent.py`（工具白名单 + effect 分级） |
| 领域层 | `domain.py`（确定性计费引擎） | `core/engine.py`（核对 + 审核状态机） |
| 知识层 | `rag_service.py`（FAISS + BM25 + PDF） | `core/knowledge.py`（关键词检索 P-01~P-08） |
| 鉴权 | JWT + HttpOnly Cookie，employee/admin | 无（仅本机演示） |

### 0.3 关键业务基线（金额唯一来源 `domain.validate_bill()`）

| 账单 | 结论 | 差异 | 精确差额 | 关键断言值 |
|---|---|---|---|---|
| B202610-SF-001 顺丰 | fail | 3 处 | **4169.61 元** | charged 16713.60 / expected 12543.99；最大差异=重复计费 3360.00（P-04） |
| B202609-HD-001 华东 | fail | 1 处 | **540.80 元** | 阶梯档位错误 TIER_MISMATCH（P-02） |
| B202610-ZT-001 中通 | pass | 0 处 | **0.00 元** | 逐行复算一致 |

**金额断言精度：一律精确到 0.01 元（分），采用 `==` 精确比对，不使用模糊区间。**

## 1. 测试策略与量化目标总览

### 1.1 五类场景定义

| 场景 | 定义 | 关注点 |
|---|---|---|
| 正常（Normal） | 合法输入、完整流程、主路径 | 金额正确、状态机正确、引用正确 |
| 边界（Boundary） | 极限值、临界值、等价类边界 | 不越界、不误判、临界点归属正确 |
| 对抗（Adversarial） | 恶意/畸形输入、攻击载荷 | 注入 0 成功、数据 0 篡改、服务不崩溃 |
| 权限（Authorization） | 未登录、越权、角色隔离 | 越权成功率 = 0、401/403 判定正确 |
| 故障（Fault） | 依赖不可用、超时、中断、降级 | 优雅降级、探针正确、可恢复 |

### 1.2 量化 KPI（通过红线）

| 指标 | 目标阈值 | 不达标判定 |
|---|---|---|
| 正常场景通过率 | **100%** | 任一用例失败即不通过 |
| 金额断言精度 | 精确到 **0.01 元**，`==` 比对 | 任何一分钱偏差即失败 |
| 边界点覆盖 | 每个边界点 ≥1 条断言，覆盖率 **100%** | 缺边界点即不通过 |
| 对抗·注入执行成功率 | **0%** | 任何注入载荷被执行即不通过 |
| 对抗·数据篡改 | **0 条** | 恶意输入改变任何数据即不通过 |
| 权限·越权成功率 | **0%** | 任何越权访问返回非 401/403 即不通过 |
| 权限·错误码正确率 | **100%**（401 未登录 / 403 越权） | 状态码或错误码不符即失败 |
| 故障·降级正确率 | **100%**（降级不拖垮、探针准确） | 依赖故障导致进程崩溃即不通过 |
| 错误码断言率 | **100%**（每个异常路径断言 code） | 只断言状态码不断言 code 视为不完整 |

## 3. 边界场景（Boundary）

> 目标：验证极限值与临界点归属。凡业务含"≤/</上限/下限"处，均取边界点 ±0.01 双测。

### 3.1 计费边界值表（用于构造断言）

| 边界点 | 规则 | 边界取值 | 预期归属 |
|---|---|---|---|
| 抛比临界 | 体积重 = 体积×1,000,000÷抛比 | 体积重 = 实重 时 weight_basis 切换 | 相等时按"实重"（`>` 才取体积重） |
| 最低收费 | base < min_charge 补足 | base = min_charge | 恰好等于不补足、少 0.01 补足 |
| 阶梯档位 | 华东 500/2000 kg | 500.00、500.01、2000.00、2000.01 | 500→1.8；500.01→1.6；2000→1.6；2000.01→1.4 |
| 称重偏差 | 容差 5% | 偏差 5.00%、5.01% | 5.00% 通过、5.01% 拒绝 |
| 争议额度 | 顺丰 8 万、华东 5 万 | 差额=剩余额度 | 超上限触发审批提示 |
| 单笔审批线 | 单笔差额 > 1 万需审批 | 9999.99、10000.00、10000.01 | >1 万标记审批 |
| 文本长度 | bill_no≤40、question≤500(MVP)/2000(主)、statement≤1200 | 40/41、500/501、1200/1201 | 越界返回 400 + 对应 code |

### 3.2 边界用例

| 编号 | 测试目标 | 输入/操作 | 预期结果 | 量化判定 |
|---|---|---|---|---|
| B-01 | 账单号长度下界 | bill_no = "" | 400 EMPTY_BILL_NO | `== 400` 且 code `== "EMPTY_BILL_NO"` |
| B-02 | 账单号长度上界 | bill_no = 40 字符 | 正常进入业务（404 BILL_NOT_FOUND 而非 400） | code `== "BILL_NOT_FOUND"` |
| B-03 | 账单号越界 | bill_no = 41 字符 | 400 BAD_BILL_NO | `== 400` 且 `== "BAD_BILL_NO"` |
| B-04 | 问题长度上界 | question = 500 字符 | 正常处理 | 不抛 QUESTION_TOO_LONG |
| B-05 | 问题越界 | question = 501 字符 | 400 QUESTION_TOO_LONG | `== 400` 且 code 正确 |
| B-06 | 阶梯档位临界 500 | 计费重量 = 500.00 | 单价 1.8（落 ≤500 档） | `== 1.8` |
| B-07 | 阶梯档位临界 500.01 | 计费重量 = 500.01 | 单价 1.6（落 500-2000 档） | `== 1.6` |
| B-08 | 阶梯档位临界 2000.01 | 计费重量 = 2000.01 | 单价 1.4（落 >2000 档） | `== 1.4` |
| B-09 | 最低收费补足 | 顺丰 base 略 < 80 元 | expected = min_charge=80.00 | `== 80.00` |
| B-10 | 最低收费恰好 | base = 80.00 元 | 不额外补足 | 与公式计算值精确相等 |
| B-11 | 称重偏差临界通过 | 偏差 = 5.00% | admissible=True | `== True` |
| B-12 | 称重偏差临界拒绝 | 偏差 = 5.01% | admissible=False，reasons 含偏差说明 | `== False` |
| B-13 | 审核决策枚举边界 | decision 非 acknowledge/reject | 400 BAD_DECISION | `== 400` 且 code 正确 |
| B-14 | 终审动作枚举边界 | action 非 confirm/cancel | 400 BAD_ACTION | `== 400` 且 code 正确 |
| B-15 | 分页 limit 下界 | limit=0 / 负数 | 被约束到合法区间（主项目 Query ge） | 不出现 `LIMIT -1` 全量返回 |
| B-16 | 空问题边界 | question="" | 400 EMPTY_QUESTION | `== 400` 且 code 正确 |

## 4. 对抗场景（Adversarial）

| 编号 | 攻击类型 | 输入/操作 | 预期结果 | 量化判定 |
|---|---|---|---|---|
| A-01 | SQL 注入 | bill_no=`"'; DROP TABLE users;--"` | 404 BILL_NOT_FOUND，无表删除 | code `== "BILL_NOT_FOUND"`，DB 完好 |
| A-02 | SQL 注入·问答 | question=`"' OR 1=1 --"` | 返回 not_found 或 400，不报 500 | 状态码 ∈ {200,400}，非 500 |

### 7.2 一票否决（停止条件，任一条命中即判不通过）

1. 任何金额断言出现分位（0.01 元）级偏差。
2. 任何注入载荷被执行或改变数据。
3. 任何越权访问返回非 401/403。
4. 依赖故障导致进程崩溃或堆栈外泄。

### 7.3 性能补充阈值（非红线，作为回归观察）

| 项 | 阈值 |
|---|---|
| 确定性核对（单账单） | < 100 ms |
| 登录 PBKDF2 校验 | 恒定耗时（防时序枚举，方差 < 5%） |
| 错误响应（含超长输入） | < 1 s |

## 9. 风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| 金额断言依赖 `domain.py` 样例数据 | 样例变动会导致测试漂移 | 断言值已锁定；改动需同步更新本方案 |
| MVP 内存态（`_REVIEWS`/`_DRAFTS`）跨用例污染 | 审核链用例相互干扰 | 每个用例 `setUp` 调 `_reset_state()` |
| 模型/向量库为外部依赖 | 故障场景需 mock 才能稳定复现 | 用 `unittest.mock.patch` 注入，不依赖真实模型 |
| 主项目生产态需 HTTPS/COOKIE_SECURE/METRICS_TOKEN | 部署期配置 | 权限/对抗用例在开发态与生产态各跑一遍 |
