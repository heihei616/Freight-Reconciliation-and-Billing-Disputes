# 物流费对账与争议 MVP

这是从主项目抽出的**可独立演示、可离线验证**的最小可行产品。它不依赖大模型、向量数据库或 SQLite，用三栏单页串起完整业务闭环：

> 选择账单 → 确定性核对 → 查看差异与复算步骤 → 制度问答 → 生成争议草稿 → 人工确认

MVP 复用主项目 `src/logistics_agent/core/domain.py` 的样例运单、价目与 `validate_bill()`。它不会另写一套运费公式，因此轻量版与正式版的金额结论保持一致。

## 已实现能力

- **三张样例账单**：顺丰账单有 3 处差异、中通账单通过、华东账单有阶梯档位错误。
- **确定性核账**：展示账单金额、应收金额、逐行差额、最大差异、价目版本和完整复算步骤。
- **制度检索**：本地解析 P-01～P-08，回答附条款出处；未命中明确返回“未找到”。
- **账单问答**：差额原因、争议额度和称重单要求直接读取当前账单事实。
- **争议草稿**：只能根据核对结果生成，客户端不能传入或修改主张金额。
- **人工确认**：待确认、已确认、已取消三个状态；终态草稿重复操作返回 409。
- **安全渲染**：页面动态内容使用 DOM `textContent`，不拼接未转义的业务 HTML。

## 启动

### 环境要求

- Python 3.11 及以上。
- 主项目 `requirements.txt` 中的 FastAPI、Uvicorn 等依赖已安装。
- 不需要模型密钥，不需要联网，不需要初始化数据库。

在项目根目录执行：

```bash
# 可选：先跑 16 项离线验收
python mvp/check_mvp.py

# 启动，默认仅监听本机 8010 端口
python mvp/app.py --port 8010
```

浏览器打开 <http://127.0.0.1:8010>。健康检查为 <http://127.0.0.1:8010/api/health>。

Windows CMD 与 Git Bash 命令相同。若 8010 被占用，可换端口：

```bash
python mvp/app.py --port 8011
```

## 三分钟演示脚本

### 1. 找出三处真实差异

默认选中 `B202610-SF-001`。页面应显示：

- 核对不通过，共 3 处差异；
- 合计多收 **4,169.61 元**；
- 第 1 行体积重抛比用错，多收 694.41 元；
- 第 2 行燃油费率沿用旧版本，多收 115.20 元；
- 第 4 行同一运单重复计费，多收 3,360.00 元。

展开“查看复算过程”，说明金额来自确定性代码而不是模型心算。最大差异是重复计费，不是第一处差异。

### 2. 用制度回答“为什么”

在右侧依次点击：

- “为什么这张账单多了钱？”
- “争议额度还剩多少？”
- “称重单要满足什么条件？”

预期回答分别引用 P-01/P-03/P-04、P-05、P-06。再输入“员工年终奖如何计算”，应明确回答未找到相关制度，不编造条款。

### 3. 证明 AI 不能直接动账

点击“生成争议单”，在弹窗中核对争议对象、4,169.61 元主张金额、三条差异与证据状态，再点击“确认提交复核”。

左侧“最近争议草稿”出现“已确认”。再次通过接口确认同一草稿会返回 409；页面上的终态草稿只提供查看，不再显示确认按钮。

### 4. 对照通过账单与阶梯错误

- 选择 `B202610-ZT-001`：差额为 0，不显示“生成争议单”。
- 选择 `B202609-HD-001`：差额为 **540.80 元**，差异类型为“阶梯档位”，依据 P-02。

## 接口

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 服务与制度语料状态 |
| GET | `/api/bills` | 三张样例账单摘要 |
| POST | `/api/audit` | 按 `bill_no` 返回核对、差异、步骤与条款 |
| POST | `/api/answer` | 按 `question`、可选 `bill_no` 回答 |
| GET | `/api/drafts` | 当前进程内的争议草稿 |
| POST | `/api/drafts` | 根据 `bill_no` 创建待确认草稿，返回 201 |
| POST | `/api/drafts/{draft_id}/decision` | `confirm` 或 `cancel`，终态重复操作返回 409 |

业务错误统一包含 `code`、`detail`、`message`，不会把关键业务失败伪装成 HTTP 200。

## 与正式版的边界

这个 MVP 用于验证业务闭环和演示交互，**不能直接暴露到公网或代替正式版上线**：

| 维度 | MVP | 正式版 |
|---|---|---|
| 检索 | 本地关键词匹配 | FAISS + BM25 混合检索 |
| 决策 | 明确的确定性意图路由 | 模型决策 + 工具白名单 + Agent 循环 |
| 金额 | 复用 `domain.validate_bill()` | 同一个确定性领域引擎 |
| 草稿存储 | 进程内存，重启清空 | SQLite 持久化、确认状态可恢复 |
| 身份与权限 | 无登录，仅本机演示 | JWT HttpOnly Cookie、角色与归属校验 |
| 写操作 | 只改变演示草稿状态 | 人工确认后进入正式复核流程 |
| 运维 | 健康检查与结构化错误 | 探针、指标、限流、审计、备份、预检 |

真实落地时，应优先把 `engine.py` 的展示层对接到正式版已有校验记录与草稿接口，而不是把 MVP 的内存状态机直接扩成生产实现。
